# SFMap

SFMap — production-карта автомобильного сообщества Москвы и Московской области. Публичная карта показывает опубликованные поля участников, а закрытая админка позволяет добавлять, редактировать и удалять записи. Основное хранилище — встроенная SQLite-база.

## Возможности

- React, MapLibre GL и Express;
- справочник районов Москвы и городов области с проверкой координат;
- SQLite в каталоге DATA_DIR с WAL, транзакциями и защитой от конфликтующих правок;
- отдельные listener-ы для карты и админки;
- админка с одноразовым challenge, Ed25519-подписью, JWE-файлом ключа, scrypt-хешем пароля, HttpOnly-сессией и CSRF;
- ручная загрузка фотографий через админку с поворотом по EXIF и сжатием в WebP до 1280×720;
- постоянные короткие ссылки на записи вида /p/<shareId> и кнопка «Поделиться»;
- статистика участников и отдельные типы точек: гараж, сервис и место встречи;
- быстрые фильтры типов, владельцы гаражей, копирование координат и переход в навигацию;
- необязательные точные координаты участников и мест, рынок JDM/USDM/EDM;
- настройки шрифта, размеров маркеров и объединения в админке;
- серверный кэш стилей, тайлов, шрифтов и спрайтов карты OpenFreeMap;
- Docker, Docker Compose и пошаговый установщик install.sh для Linux.

## Установка на Linux

На сервере нужны Git, curl и доступ к sudo. Скопируйте блок целиком: он скачает проект в `/opt/sfmap` и запустит пошаговую установку. Авторизация в GitHub не требуется.

```bash
sudo install -d -o "$(id -un)" -g "$(id -gn)" /opt/sfmap && \
git clone https://github.com/Desmont0/SFMapMSK.git /opt/sfmap && \
cd /opt/sfmap && \
bash install.sh
```

Установщик проверит Linux и права администратора, при необходимости установит Docker Engine и Compose v2, затем предложит режим сети: только локальный, карта на выбранном LAN-адресе с локальной админкой, публичная карта с локальной админкой или публичная карта с удалённой админкой, доступной только с одного указанного IP. Он проверяет формат и занятость портов, готовность Docker и health-check приложения. Пароль администратора вводится скрыто и не сохраняется в `.env`; при повторном запуске прежний `.env` сохраняется в резервную копию, а ключ и сессии администратора перевыпускаются.

После запуска установщик показывает адрес карты, путь к `secrets/admin-access.txt`, JWE-файлу и SSH-команду для админки:

    ssh -L 3000:127.0.0.1:3000 user@server

Откройте адрес из `secrets/admin-access.txt` через `http://localhost:3000`. Для входа нужны файл ключа и пароль. В режиме 4 установщик настраивает HTTPS на выбранном домене/IP сервера: можно указать готовый PEM-сертификат/fullchain и приватный ключ либо создать самоподписанный сертификат. Самоподписанный сертификат `secrets/tls.crt` добавьте в доверенные на компьютере администратора. Браузеру нужен доверенный HTTPS для работы с файлом ключа через WebCrypto. Сертификат должен соответствовать домену или IP сервера.

Для режима 4 нужен Docker Compose **2.24.4 или новее**. Он использует host networking на Linux, чтобы приложение видело настоящий IP соединения. Приложение возвращает 404 для страницы админки и всех `/api/admin/*` с других IP; поддельные `X-Forwarded-For` и `Forwarded` доступ не дают. Подключайтесь к порту HTTPS-админки напрямую: reverse proxy изменит IP соединения. Публичную карту можно отдельно публиковать через reverse proxy с HTTPS. HSTS отключён, поскольку на том же серверном имени может работать отдельный HTTP-порт карты.

Установщик предлагает правила UFW/firewalld для порта карты и отдельно для IP администратора; без ответа `y` firewall не меняется. При смене внешнего IP измените `ADMIN_ALLOW_IPS` в `.env`, правило firewall и выполните `docker compose up -d`. Для продления TLS замените `secrets/tls.crt` и `secrets/tls.key` с сохранением прав, затем выполните `docker compose restart sfmap`. Автоматического продления сертификатов нет.

## Ручной запуск

Требуется Node.js 26 и npm:

    npm ci
    cp .env.example .env
    mkdir -p data secrets
    chmod 700 data secrets
    SFMAP_ADMIN_PASSWORD='длинный пароль' npm run setup-admin
    npm run build
    npm start

Для разработки используйте npm run dev. В .env задаются DATA_DIR, SECRETS_DIR, HOST, PORT, PUBLIC_ORIGIN, SHARE_PORT, SHARE_BIND и MAP_CACHE_AUTO. Для встроенного HTTPS задайте TLS_CERT_FILE, TLS_KEY_FILE, HTTPS PUBLIC_ORIGIN и COOKIE_SECURE=true.

## Docker Compose

    cp .env.example .env
    mkdir -p data secrets
    chmod 700 data secrets
    docker compose build
    docker compose run --rm --no-deps --user 0 --cap-add CHOWN --cap-add FOWNER --cap-add DAC_OVERRIDE --entrypoint /bin/sh sfmap -c 'chown -R 1000:1000 /app/data /app/secrets'
    printf '%s\n' 'длинный пароль' | docker compose run --rm --no-deps -T sfmap npm run setup-admin -- --password-stdin
    docker compose up -d

SQLite и фотографии хранятся в именованном томе <имя-проекта>_sfmap-data, а ./secrets подключается отдельно. Данные и секреты не попадают в образ. Проверка состояния публичного listener-а: curl http://127.0.0.1:3001/api/health.

Основной listener использует HOST_BIND:PORT и принимает админские запросы. Публичный listener использует SHARE_BIND:SHARE_PORT и отдаёт только карту и публичный API. В локальном режиме оба адреса привязаны к 127.0.0.1; для LAN или внешнего доступа меняйте SHARE_BIND и открывайте SHARE_PORT в firewall.

`ADMIN_ALLOW_IPS` задаёт точный список IP, которым разрешены страница админки и `/api/admin/*`. В установщике режим 4 заполняет это значение одним IPv4. Ограничение действует внутри приложения по IP соединения и дополняет правила firewall.

## Обновление без потери пользователей

После первоначальной установки обновляйте сервер из каталога checkout:

    cd /opt/sfmap
    bash update.sh

Скрипт проверяет отсутствие незакоммиченных и посторонних новых файлов, получает fast-forward изменения из origin/main и определяет существующий контейнер и том SQLite. До изменения исходников он останавливает запись и создаёт каталог backups/ДАТА-PID/ со снимком database.sqlite через VACUUM INTO, конфигурацией .env (файл env), архивом ключей и сертификатов secrets.tar.gz, исходным commit и конфигурацией Compose. Текущий Docker-образ сохраняется с тегом sfmap-rollback:ДАТА-PID.

Существующий том закрепляется в .sfmap-volume.yaml. Затем скрипт собирает новую версию, выполняет npm run db:migrate, проверяет целостность SQLite, сохранение ID участников и доступа администратора, запускает контейнер и проверяет health-check. Миграции схемы используют PRAGMA user_version и транзакции; более новая неподдерживаемая схема отклоняется. На время копирования, сборки и миграции сайт остановлен.

При ошибке update.sh возвращает прежний commit, восстанавливает SQLite и запускает сохранённый образ без повторной сборки. Если восстановление или запуск не удались, сервис остаётся остановленным; скрипт сообщает путь к копии для восстановления. Копии и старые образы остаются после успешного обновления: храните копии отдельно от сервера и удаляйте устаревшие после проверки новой версии. Не удаляйте Docker-том базы.

Скрипт требует существующий контейнер. Если контейнер удалён, сначала запустите прежнюю версию из исходного каталога с тем же именем проекта Compose. Не переименовывайте каталог до первого обновления, которое закрепит том. Повторный install.sh перевыпускает ключ администратора; для штатного обновления используйте update.sh.

### Первый переход со старой версии без update.sh

Получите новый скрипт во временный файл, сохранив исходный checkout до резервного копирования:

    cd /opt/sfmap
    git fetch origin main
    upgrade_script=$(mktemp)
    git show origin/main:update.sh > "$upgrade_script"
    bash "$upgrade_script" "$PWD"
    rm -f "$upgrade_script"

Для ручной установки без Docker остановите процесс, сохраните DATA_DIR и secrets, обновите исходники, выполните npm ci, npm run build и npm run db:migrate, затем запустите приложение. При откате возвращайте исходники и снимок базы одной версии.

## SQLite и резервные копии

Основной файл — data/sfmap.sqlite при ручном запуске или том sfmap-data в Compose. Для согласованной копии выполните `VACUUM INTO` внутри работающего контейнера:

    docker compose exec -T sfmap node --input-type=module -e "import {DatabaseSync} from 'node:sqlite'; const db=new DatabaseSync('/app/data/sfmap.sqlite'); db.exec(\"VACUUM INTO '/tmp/sfmap-backup.sqlite'\"); db.close();"
    docker compose cp sfmap:/tmp/sfmap-backup.sqlite ./sfmap.sqlite.backup

Восстановление выполняйте при остановленном контейнере. Резервные копии храните отдельно от сервера.

### Перенос пользователей на другой сервер

Установите проект на новом сервере, сохраните текущую целевую базу отдельно, затем скопируйте database.sqlite из выбранного каталога резервной копии в backups/import/database.sqlite. Импортируйте снимок и примените миграции новой версии:

    cd /opt/sfmap
    docker compose stop sfmap
    docker compose run --rm --no-deps -T sfmap node --input-type=module -e "import fs from 'node:fs'; const chunks=[]; for await(const c of process.stdin)chunks.push(c); fs.writeFileSync('/app/data/sfmap-import.tmp',Buffer.concat(chunks),{mode:0o600}); for(const s of ['-wal','-shm'])fs.rmSync('/app/data/sfmap.sqlite'+s,{force:true}); fs.renameSync('/app/data/sfmap-import.tmp','/app/data/sfmap.sqlite');" < backups/import/database.sqlite
    docker compose run --rm --no-deps -T sfmap npm run db:migrate
    docker compose up -d --wait --wait-timeout 120

Если вашему пользователю нужен sudo для Docker, используйте sudo docker. Вместе с базой сохраняется **старый ключ администратора**: используйте прежний JWE-файл и пароль. Ключ, созданный установщиком нового сервера до импорта, перестанет подходить. При необходимости распакуйте secrets.tar.gz в отдельный каталог и сохраните прежний JWE-файл. Сетевые настройки и TLS в .env оставьте настроенными для нового сервера; сертификат должен соответствовать новому домену. Используйте скрытый путь из прежнего admin-access.txt с новым доменом и портом. Фотографии входят в снимок SQLite и TXT-экспорт.

## Фотографии, ссылки и статистика

Фотографии добавляются вручную в форме записи админки. Поддерживаются JPEG, PNG, WebP и AVIF размером до 12 МБ. Сервер поворачивает изображение по EXIF, не увеличивает маленькие файлы и сохраняет оптимизированный WebP в пределах 1280×720. Фото хранится в таблице photos, поэтому оно переносится вместе с базой и попадает в резервный TXT-экспорт как base64.

У каждой записи есть постоянный короткий идентификатор. Ссылка `/p/<shareId>` открывает карту с выбранной карточкой и приближает её местоположение. API записи — `/api/participants/<shareId>`. Кнопка «Поделиться» сразу копирует ссылку в буфер обмена. Если встроенный браузер запрещает копирование, ссылка появляется в поле для ручного копирования. Системное окно выбора приложения не открывается.

Кнопка «Статистика» открывает панель с компактной строкой количества участников и мест. Панель закрывается при нажатии на карту, вне панели или Escape. В ней показываются районы и города, годы выпуска, цвета, двигатели, КПП, тип двигателя, рынок и поле «Люкатый». Автомобильная статистика учитывает участников. Верхние кнопки «Все», «Участники», «Гаражи», «Сервисы», «Встречи» фильтруют карту и поиск; статистика остаётся общей.

## Участники, гаражи и координаты

Участнику можно указать рынок JDM, USDM или EDM; КПП — АКПП или МКПП. У гаража есть необязательный владелец из существующих участников. Его имя в карточке ведёт на карточку участника. Перед удалением владельца или сменой его типа сначала отвяжите связанные гаражи.

Для любой записи можно заполнить оба поля «Точная широта» и «Точная долгота». Они имеют приоритет над центром района или города. Координаты должны находиться в Москве или Московской области. Чтобы вернуться к центру района, очистите оба поля. В карточках мест и участников с точными координатами есть кнопки копирования координат и открытия Яндекс Карт для навигации. Ссылки HTTP/HTTPS в публичных комментариях кликабельны.

В админке, в блоке «Вид кружочков на карте», задаются шрифт (Arial, системный или Manrope), размер букв, диаметр кружочков и радиус объединения. Радиус 0 отключает объединение. По умолчанию используются Arial и буквы размером 18 px. Группы привязаны к точным координатам реальной записи; положение больше не берётся из округлённой геометрии векторных тайлов.

При обновлении существующая SQLite-база, ID, фотографии, короткие ссылки и ревизии сохраняются. Новые поля получают значения при чтении; точные координаты старых мест сохраняются. Рынок автоматически из стороны руля не выводится: заполните его вручную. Устаревшие значения «Робот» и «Вариатор» отображаются как неуказанная КПП. Схема SQLite остаётся версии 2; используйте штатный `update.sh` с резервным копированием.

## Экспорт и кэш карты

Для аварийного ручного извлечения данных остановите контейнер после последней записи и выполните:

    docker compose run --rm --no-deps sfmap npm run db:export > sfmap-export.txt

В работающей админке тот же экспорт доступен по GET /api/admin/export.txt. В файл входят закрытые поля, короткие ссылки и фотографии WebP в base64.

Карта обслуживается через локальный кэш в DATA_DIR/map-cache. При MAP_CACHE_AUTO=true сервер заполняет его при старте и повторяет недостающие ресурсы каждые 30 минут. Для принудительного заполнения выполните npm run map:cache. Если внешний сервис карты временно недоступен, уже загруженные стили и тайлы продолжают отдаваться из кэша.

Публичные запросы не расходуют лимит админского API, поэтому посетители за одним прокси или NAT не блокируют друг друга. Запросы данных и стилей ограничены по времени; карта показывает ошибку с кнопкой «Повторить» и делает до трёх автоматических попыток. Карточка по прямой ссылке доступна даже при сбое подложки. После возвращения во вкладку или восстановления сети соединение проверяется повторно. Для телефонов ограничена плотность рендеринга карты и добавлено восстановление после потери WebGL-контекста; панель управления учитывает горизонтальный экран и безопасные области iPhone. Ресурсы карты разрешаются относительно адреса страницы, включая HTTPS за reverse proxy.

## Проверки

    npm ci
    npm run build
    npm test
    npm audit --audit-level=low

Браузерные проверки Chromium и WebKit запускаются после сборки:

    npx playwright install chromium webkit
    npm run test:browser

На Linux для установки системных зависимостей браузеров используйте `npx playwright install --with-deps chromium webkit`. Проверки создают отдельную временную базу и используют порт 18765. Они проверяют прямые ссылки, копирование без системного меню, фильтры, закрытие статистики, горизонтальный экран, админку и восстановление карты. Основной набор использует управляемые ответы ресурсов карты; дополнительная проверка реального публичного кэша включается переменной `SFMAP_LIVE_MAP=true`.

Тесты проверяют географию, валидацию, CRUD SQLite, сохранение после перезапуска, ревизии и откат транзакций, вход по ключу, сессии, CSRF, разграничение listener-ов, очистку устаревших телефонных полей, ручную загрузку и удаление фотографий, короткие ссылки и TXT-экспорт.

Также проверяются миграции заполненной базы, HTTPS-вход, запрет доступа с постороннего IP и подделка forwarded-заголовков. Linux CI проверяет обновление с сохранением записей, откат после миграции, которая изменила данные и завершилась ошибкой, и локальный/удалённый режимы установщика. tests/deployment.sh предназначен только для изолированного CI checkout: он создаёт тестовые commit-ы и меняет origin.

## Структура данных

- server/db.ts и server/migrations.ts — SQLite и версионированные миграции (текущая схема 2);
- server/repository.ts — транзакционный репозиторий участников;
- server/auth.ts — challenge, Ed25519/JWE, сессии и CSRF;
- server/photos.ts и server/export.ts — фотографии и резервный TXT-экспорт;
- server/map-cache.ts — локальный кэш карты;
- shared/locations.json — справочник мест;
- install.sh и update.sh — установка и обновление на Linux;
- compose.yaml и Dockerfile — контейнерный запуск.

Лицензии геоданных и источники указаны в public/geo/LOCATIONS.md и public/geo/SOURCE.md.
